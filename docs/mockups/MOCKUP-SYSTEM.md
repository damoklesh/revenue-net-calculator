# Mockup System for NetSalary

## Visual direction
The mockups should follow a professional, careful and adult visual language inspired by the trust signals people expect when consulting an accounting or payroll professional.

### Design keywords
- Trustworthy
- Clear
- Reassuring
- Precise
- Calm
- Professional
- Contemporary, but not playful

### Recommended UI style
- Clean layouts with generous spacing and a clear visual hierarchy.
- Neutral background colors (white, off-white, very light gray).
- Primary colors in navy, slate or deep teal.
- Very restrained use of green for success or positive net-result cues.
- Soft borders, subtle shadows and rounded corners used sparingly.
- Minimal illustration; rely mainly on forms, cards, tables and explanatory blocks.
- Clear labels, helper text and legal/fiscal reassurance microcopy.
- Avoid flashy gradients, loud colors, gaming aesthetics or startup-style exaggeration.

### Recommended typography
- Use a sober sans-serif such as Inter, Source Sans 3 or similar.
- Headings should feel formal and readable.
- Body text should prioritize legibility over personality.
- Numeric values should be highly legible and visually stable.

### UI behaviour principles
- Information should feel structured and predictable.
- Important fiscal outputs should be emphasized with calm, high-contrast cards.
- Inputs, warnings and assumptions should be explicit.
- Show transparency and methodology access without overwhelming the main journey.

## Mockup file strategy
Use one mockup per file whenever possible. This is the best option for agentic implementation because it makes references precise, reduces ambiguity and allows each user story to point to one or more exact visual sources.

## Naming convention
Each mockup file should have:
- a unique code visible inside the image itself, for example `MK-004`
- a descriptive filename
- a direct link from one or more user stories

Recommended pattern:
`docs/mockups/MK-XXX-descriptive-name.png`

Inside the image, place the code in a small top-right badge, for example:
`MK-004 · Results breakdown`

## Precedence rule
When a conflict exists:
1. Acceptance Criteria
2. User Story scope and context
3. Mockup
4. Visual polish preferences
