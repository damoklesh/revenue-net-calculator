# US-008 — Calculate Spanish IRPF withholding

## User Story
As an employee in Spain, I want an automatically estimated withholding rate or my known rate applied so that I can estimate take-home salary.

## Context
US-007 supplies employee contributions. Automatic mode supports an active employee, family situation 3, age 18–64, without dependants, disability, special deductions or regularization, in common territory excluding special territories. Use the AEAT 2026 algorithm effective from 2026-09-10 as a versioned annual simulation.

Dependency contract: US-007 supplies Spanish employee contributions and validated Spain-specific inputs. This story owns IRPF withholding only. It must preserve the distinction between automatic AEAT estimation and user-supplied manual rate because US-009 and US-010 present the selected tax mode.

There is no dedicated mockup. The output must remain presentation-neutral and include rule version, assumptions and warnings required by the later results and methodology screens.

## Scope
- In scope: Supported local AEAT algorithm branch, manual rate, tax-mode selection and verifiable reference fixtures.
- Out of scope: Final regional income-tax liability, foral regimes, special territories, dependants and mid-year withholding regularization.

## Acceptance Criteria
- [ ] AC-1: Automatic withholding implements the admitted branch of the specified AEAT algorithm entirely locally, with no runtime AEAT API calls.
- [ ] AC-2: It uses calculated contributions, employment expenses, reductions, personal minimum, limits and official operation order and rounding.
- [ ] AC-3: It handles low-income thresholds and applicable fixed-term minimum rates rather than applying marginal brackets directly to gross salary.
- [ ] AC-4: Manual mode accepts a 0–100% user-provided rate and applies it to gross G.
- [ ] AC-5: Outputs are labelled estimated IRPF withholding and do not claim to determine final annual or regional tax liability.
- [ ] AC-6: The result identifies ES-IRPF-2026-09-10 and does not silently substitute an earlier algorithm.
- [ ] AC-7: At least three documented official-reference fixtures cover a supported low salary, EUR 36,000 and EUR 75,000; inputs, version and outputs are recorded. Missing evidence is reported as a concrete blocker rather than fabricated.

- [ ] AC-8: Automatic and manual modes return the same common result shape and identify the exact algorithm/ruleset version used.
- [ ] AC-9: No production runtime path fetches the AEAT calculator/specification or depends on external network availability.

## Technical Notes
- Preserve the existing stack and conventions where present.
- Automatic profile: active employee, family situation 3, under 65, no dependants or special circumstances. Do not collect NIF for this local mathematical estimate.
- Implement deductible expenses, low-income reductions, personal minimum, progressive scale, exemption thresholds, quota limits and official withholding-rate rounding from the reference PDF. Do not simply subtract the personal minimum from the tax base.
- Manual withholding=G×rate/100; annual payroll net=G-C-withholding. ES-01 at a manual 15% gives withholding=5400 and net=28260.
- Official specification: https://sede.agenciatributaria.gob.es/static_files/Sede/Programas_ayuda/Retenciones/2026/Algoritmo%20Retenciones-2026_10sept.pdf ; version index and calculators: https://sede.agenciatributaria.gob.es/Sede/Retenciones.shtml .
- The versioned simulation does not reconstruct withholding already made before 2026-09-10. Test fixtures are local; automated test execution must not depend on live official services.


- Implementation plan:
  1. Represent Spain tax mode explicitly as `manual` or `automatic-aeat-2026-09-10` and validate the supported automatic profile before calculation.
  2. Implement manual withholding as a small pure path: validate `[0,100]`, calculate `G * rate / 100`, apply shared rounding and subtract after employee contributions.
  3. For automatic mode, transcribe the supported AEAT operation sequence into named pure helpers matching the official algorithm concepts rather than a single formula.
  4. Store algorithm constants/tables in the Spain ruleset with version `ES-IRPF-2026-09-10`; reject/make unavailable any automatic path whose required parameters or captured fixtures are missing.
  5. Apply deductible expenses, low-income reductions, personal minimum treatment, progressive operations, quota limits, thresholds and official rate rounding in specification order.
  6. Keep the algorithm local: no fetch/XHR to AEAT at runtime or during automated tests.
  7. Build at least three immutable official-reference fixture files with documented inputs, source/version and expected outputs; treat discrepancies as implementation blockers, never invent values.
  8. Return `estimated IRPF withholding` metadata and a warning that this is not final regional income-tax liability.
- Separate contribution input/result from IRPF logic so US-007 fixtures remain stable when withholding evolves.
