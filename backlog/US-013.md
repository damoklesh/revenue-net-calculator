# US-013 — Export simulations as CSV and JSON

## User Story
As a user, I want to download simulation results so that I can retain or compare them outside the application.

## Context
A valid current calculation supplies normalized inputs, results and rule metadata. Exports must be generated in the browser without sending salary data to a service.

Mockup references:
- `docs/mockups/MK-008-export-actions.png`
Use the export-actions mockup as the primary reference for export controls, format selection and export-state messaging.
Implementation note: Acceptance Criteria take precedence over the mockup if a conflict exists.

Dependency contract: US-009 provides a current non-stale `SalaryResult` and normalized inputs. Export generation must consume that model directly and must not trigger recalculation or network access. US-015 may later add custom-rule provenance; design the export schema so that warning metadata can be added without breaking existing fields.

Use `MK-008` for format choice, enabled/disabled states, local-processing reassurance and export-content hierarchy. The accepted formats remain CSV and JSON only.

## Scope
- In scope: UTF-8 CSV and structured JSON downloads, result metadata, delimiter escaping and formula-injection protection.
- Out of scope: PDF generation, external storage, stale-result exports and backend export services.

## Acceptance Criteria
- [ ] AC-1: CSV breakdown and JSON exports are generated locally using Blob and a user-triggered download.
- [ ] AC-2: Both exports contain inputs, results, country, currency, mode, rule version and assumptions.
- [ ] AC-3: JSON uses canonical numeric values; CSV documents its separator and preserves monetary precision.
- [ ] AC-4: CSV text fields neutralize spreadsheet formulas; downloads are keyboard-accessible and make no network requests.
- [ ] AC-5: Export is disabled until a valid current result exists and is disabled again when inputs invalidate it.

- [ ] AC-6: Export controls follow `MK-008` for format selection, disabled states and privacy/security messaging.
- [ ] AC-7: File names are deterministic and safe, and repeated downloads do not leak unreleased object URLs.

## Technical Notes
- Preserve the existing stack and conventions where present.
- Use explicit export schemas and standard escaping for separators, quotes and line breaks.
- Neutralize spreadsheet formula prefixes in user-controlled text; preserve valid numeric fields as numbers.
- Revoke object URLs after download; include personalized-rule warnings if US-015 has been implemented.


- Implementation plan:
  1. Define explicit versioned export DTOs from normalized input, `SalaryResult`, rule metadata and assumptions; do not serialize React state wholesale.
  2. Implement JSON export with canonical numeric types and deterministic property names/order where practical for testability.
  3. Implement CSV generation with a documented delimiter, UTF-8 encoding, standard quote escaping and stable row/column schema for the detailed breakdown.
  4. Before CSV serialization, neutralize user-controlled text beginning with spreadsheet formula prefixes `=`, `+`, `-` or `@` by prefixing an apostrophe; do not convert legitimate numeric fields into text unnecessarily.
  5. Generate files locally using Blob/object URL and a user-triggered anchor/download action; revoke the URL after use.
  6. Derive enabled state from `currentResult && !stale`; input edits immediately disable export.
  7. Follow `MK-008` for CSV/JSON choices, disabled state and local-processing messaging.
  8. Include custom-rule provenance fields/warning opportunistically when present, but do not make US-013 depend on US-015.
- Use safe deterministic filenames such as `netsalary-FR-2026-10-01.json`/`.csv` based on calculation/export date and country, sanitized for filesystem portability.
