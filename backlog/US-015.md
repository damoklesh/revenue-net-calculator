# US-015 — Import custom calculation parameters

## User Story
As a prototype evaluator, I want to load a local JSON rule set so that I can test parameter changes without editing source code.

## Context
FR/ES adapters and validated rule schemas exist. Custom rules are data for those existing adapters, not executable formulas or new country engines. Official bundled rule sets must remain intact.

Mockup references:
- `docs/mockups/MK-010-custom-rules-import.png`
Use the custom-rules import mockup as the primary reference for file import, difference preview, activation controls and warning presentation.
Implementation note: Acceptance Criteria take precedence over the mockup if a conflict exists.

Dependency contract: US-004 provides rule schemas, adapter registry and validation primitives; US-009 provides current-result invalidation and warnings. Imported data can replace parameters only for an existing adapter after complete validation. Official bundled rules remain immutable.

Use `MK-010` for file selection, validation/diff preview, explicit activation, warning treatment and restore action. Enforce the 100 KiB acceptance criterion even if the mockup visually shows a different illustrative file-size note.

## Scope
- In scope: Local JSON import, validation, parameter diff preview, explicit activation and restoration of official rules.
- Out of scope: Executing imported code, remote imports, unsupported countries and altering official bundled files.

## Acceptance Criteria
- [ ] AC-1: Import accepts a local .json file of at most 100 KiB matching an existing FR/ES adapter schema.
- [ ] AC-2: Only declarative data is accepted; executable expressions, functions, eval and new operation types are prohibited.
- [ ] AC-3: The complete file is validated before activation, differences are shown, and activation requires an explicit user action.
- [ ] AC-4: Invalid or cancelled imports leave the active calculation unchanged; the user can restore the original official rule set.
- [ ] AC-5: Custom-rule results and exports state Custom rules, not officially validated and identify the local filename.
- [ ] AC-6: Changing a supported rate changes the affected deduction and net, and registering a country without an adapter is rejected.

- [ ] AC-7: The import/diff/activation flow follows `MK-010`, but validation constraints in this story override illustrative values shown in the mockup.
- [ ] AC-8: A custom ruleset is never used merely because a file was selected; successful validation and a separate explicit activation action are both required.

## Technical Notes
- Preserve the existing stack and conventions where present.
- Treat import content as untrusted data: reject unknown/dangerous keys, non-finite values, negative rates and inconsistent brackets.
- Keep official and custom parameter objects separate; custom activation invalidates prior results until recalculation.
- Use the existing calculation and export contracts; do not add formula evaluation or a server.


- Implementation plan:
  1. Add a local file picker/drag-drop surface following `MK-010`; reject non-JSON extension/type where reliably detectable and enforce byte size `<= 100 KiB` before parsing.
  2. Parse JSON into an unknown value; reject prototype-pollution keys and validate against the existing country ruleset schema before constructing any typed object.
  3. Reject executable/formula concepts, unknown operation types, functions/expressions represented as configuration, non-finite/negative invalid values and inconsistent/overlapping brackets.
  4. Compute a declarative diff between official and candidate rulesets and display changed/added/unchanged values before activation.
  5. Keep selected/validated candidate rules separate from the active ruleset. Provide distinct `Validate` and explicit `Activate` actions.
  6. On activation, register/choose the custom parameter object only for an already-supported FR/ES adapter, mark current results stale and attach `customRules` provenance including local filename.
  7. `Restore official rules` switches back to the bundled ruleset without mutating it and invalidates results until recalculation.
  8. Ensure cancellation or validation failure leaves the active rules and current calculation unchanged.
- Never use `eval`, `Function`, dynamic module import from file content, templated expressions or remote URLs from the imported data.
