# US-011 — Compare two salary scenarios

## User Story
As a candidate, I want to compare two offers so that I can assess their difference in estimated net income.

## Context
A single scenario can already be calculated and displayed. Each comparison scenario needs independent country, gross, options, rule version and tax mode. Comparisons use annual amounts in EUR.

Mockup references:
- `docs/mockups/MK-006-scenario-comparison.png`
Use the comparison mockup as the primary reference for the side-by-side scenario layout, deltas and callout emphasis.
Implementation note: Acceptance Criteria take precedence over the mockup if a conflict exists.

Dependency contract: US-009 provides reusable result summary primitives and a calculation service. Scenario A and B should each use the same `SalaryInput -> SalaryResult` path as the normal calculator. Comparison state must be isolated from the main calculator state except when explicitly seeding a scenario.

Use `MK-006` for side-by-side scenario hierarchy, comparison table and delta callout. The UI must remain neutral: it compares values but does not recommend an employment choice.

## Scope
- In scope: Independent A/B scenarios, annual comparison table and absolute/relative net differences.
- Out of scope: Purchasing-power comparisons, exchange rates, cost of living and employment recommendations.

## Acceptance Criteria
- [ ] AC-1: A and B retain independent inputs, options, country and calculation metadata.
- [ ] AC-2: An annual comparison table shows gross, contributions, selected tax deduction and net, with absolute EUR and relative differences.
- [ ] AC-3: Relative change uses scenario A as denominator; when A's net is zero, it displays Not applicable.
- [ ] AC-4: The comparison states that it compares nominal income under displayed assumptions, not purchasing power; different tax modes are clearly identified.
- [ ] AC-5: Editing A preserves B and invalidates only A until recalculation.

- [ ] AC-6: The comparison layout follows `MK-006` at desktop and stacks scenarios without losing labels at narrow widths.
- [ ] AC-7: No comparison copy ranks, recommends or labels either employment scenario as objectively better; it reports numeric differences only.

## Technical Notes
- Preserve the existing stack and conventions where present.
- Reuse the calculation engine and result components; do not duplicate national formulas.
- Compute delta=B.annualNetAfterTax-A.annualNetAfterTax; percentage=delta/A.annualNetAfterTax×100 when the denominator is nonzero.
- Compare annual totals even if countries or payment schedules differ; retain locale-independent numeric state.


- Implementation plan:
  1. Define `ComparisonScenario` as independent normalized input + calculation status + optional current result. Maintain separate A/B instances.
  2. Seed Scenario A from the current calculator result when entering comparison if available; initialize B explicitly from A or defaults without sharing mutable references.
  3. Reuse the standard validation and `calculateSalary` path for each scenario. Editing one marks only that scenario stale.
  4. Build a comparison view-model using annual gross, employee contributions, selected tax deduction and final annual net from each result.
  5. Compute absolute delta `B-A`; compute relative delta only when A denominator is nonzero, otherwise expose `notApplicable` rather than infinity/NaN.
  6. Render side-by-side scenario summaries and the detailed table following `MK-006`; stack vertically at narrow widths while retaining A/B labels on each value.
  7. Show tax mode, country/ruleset and payment schedule for each scenario so unlike assumptions are explicit.
  8. Keep language/formatting changes presentation-only and do not recalculate numeric comparison state.
- Do not add cost-of-living, currency-conversion or recommendation logic. The comparison is descriptive and nominal.
