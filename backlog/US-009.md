# US-009 — Display net salary and a transparent breakdown

## User Story
As a user, I want to see my estimated income and its deductions so that I can understand the difference between gross and net salary.

## Context
Validated inputs and both national calculation paths are available. Result data distinguishes payroll cash deductions, tax-base deductions, withholding and projected annual tax. Numeric results remain independent of locale.

Mockup references:
- `docs/mockups/MK-004-results-breakdown.png`
Use the results mockup as the primary reference for salary summary hierarchy, breakdown cards, assumptions block and transparency messaging.
Implementation note: Acceptance Criteria take precedence over the mockup if a conflict exists.

Dependency contract: US-003 supplies valid current input state and stale-result semantics; US-006 and US-008 supply complete France/Spain results. This story is presentation-only: it must not reproduce fiscal formulas. US-010 through US-013 and US-015 reuse the current-result state and/or result components created here.

Use `MK-004` as the primary visual reference for information hierarchy: summary KPIs first, composition/reconciliation second, detailed deductions third, metadata/assumptions/warnings adjacent. Values in the mockup are illustrative; fixtures in this story are authoritative.

## Scope
- In scope: Summary cards, annual/monthly presentation, deduction table, accessible composition visualization and result states.
- Out of scope: New tax formulas, employer-cost calculations and pretending monthly averages are exact payslips.

## Acceptance Criteria
- [ ] AC-1: Cards show annual gross, annual net before tax, final annual net and monthly average net.
- [ ] AC-2: Each cash deduction line displays its concept, base, rate and amount; tax-base deductions are presented separately.
- [ ] AC-3: An accessible composition bar shows contributions, the selected tax deduction and net; an equivalent table is always available.
- [ ] AC-4: Zero gross never displays NaN, infinity or an undefined percentage.
- [ ] AC-5: Gross equals contributions plus the selected tax deduction plus final net within EUR 0.01.
- [ ] AC-6: Country, rule version, tax mode, assumptions and warnings are visible; a monthly average is not labelled as an exact 14-payment payslip.

- [ ] AC-7: The implemented desktop information hierarchy is consistent with `MK-004`; responsive reflow preserves the same semantic order.
- [ ] AC-8: Result rendering uses semantic text/table equivalents for every visual amount; color is never the sole carrier of deduction/category meaning.

## Technical Notes
- Preserve the existing stack and conventions where present.
- Consume the common SalaryResult contract without copying fiscal formulas into components.
- FR-01 known PAS 10%: G=36000, C=7502.49, payroll taxable net=29523.24, PAS=2952.32, annual net=25545.19.
- ES-01 manual IRPF 15%: G=36000, C=2340, withholding=5400, annual net=28260, monthly net in 12 payments=2355.
- Changing calculation inputs invalidates displayed results until recalculation; language-only changes preserve numeric output.
- Differentiate cash deductions from deductions used only to determine the tax base; never subtract both withholding and projected annual tax.


- Implementation plan:
  1. Create selectors/view-model helpers that transform `SalaryResult` into display groups without recomputing tax or contribution formulas.
  2. Implement the summary row from `MK-004`: annual gross, annual net before tax, final annual net and monthly average net.
  3. Implement an accessible composition view using the same numeric source as the reconciliation table. For zero gross, render zero values and suppress undefined percentages.
  4. Render deduction lines in a semantic table with concept, base, rate and amount. Keep tax-base-only adjustments in a visually and semantically separate group from cash deductions.
  5. Render country, rule version, tax mode, assumptions and warnings in an adjacent details area; projection/custom warnings must remain visible without hover.
  6. Add stale/empty/invalid states. Once calculation inputs change, hide or mark the old result as stale and disable downstream actions until recalculation.
  7. Provide reusable result primitives/selectors for comparison, history preview and export stories without coupling them to one route.
  8. Match `MK-004` desktop hierarchy while using normal document flow/grid for responsive reflow; do not encode the mockup as a fixed-size canvas.
- Reconciliation should be computed from result fields and asserted in a helper/test; the UI should not silently absorb differences greater than EUR 0.01.
- All visible labels go through US-002 translation resources; numeric formatting happens at the view boundary with `Intl`.
